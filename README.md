This repository provides a starter template for developing custom GitHub Actions with TypeScript.
It includes a pre-configured packaging pipeline using `@vercel/ncc`, unit testing with Vitest, multi-platform continuous integration, and reproducible development shells via Nix and pre-commit hooks.

---

### Usage

Add this step to your GitHub Actions workflow file (for example, `.github/workflows/main.yml`):

```yaml
- name: Run Greeting Action
  id: greet
  uses: habedi/template-github-action@v1
  with:
    name: 'Octocat'
    greeting-prefix: 'Welcome'

- name: Print Output
  run: |
    echo "Greeting: ${{ steps.greet.outputs.greeting }}"
    echo "Timestamp: ${{ steps.greet.outputs.timestamp }}"
```

---

### Inputs and Outputs

#### Inputs

| Input             | Description                                       | Required | Default   |
| :---------------- | :------------------------------------------------ | :------- | :-------- |
| `name`            | Name of the person or entity to greet             | No       | `'World'` |
| `greeting-prefix` | Greeting prefix to prepend before the target name | No       | `'Hello'` |

#### Outputs

| Output      | Description                                                  |
| :---------- | :----------------------------------------------------------- |
| `greeting`  | The formatted greeting generated by the action               |
| `timestamp` | The ISO 8601 timestamp recorded when the action was executed |

### Quickstart

#### 1. Prerequisites

You need [Node.js](https://nodejs.org/) (version 20 or higher) and [npm](https://www.npmjs.com/) installed on your machine.
Alternatively, if you use [Nix](https://nixos.org/) with flakes enabled, you can enter the development shell directly:

```shell
nix develop
```

#### 2. Installing Dependencies

```shell
make install-deps
```

#### 3. Running Tests

```shell
make test
```

#### 4. Building the Bundle

GitHub Actions run the compiled JavaScript bundle committed in the `dist/` directory.
Rebuild the bundle after modifying files in `src/`:

```shell
make build
```

#### 5. Code Quality and Formatting

```shell
make lint
make check
make format
```

> [!TIP]
> Run `make help` to see all available targets in the project's [Makefile](Makefile).
